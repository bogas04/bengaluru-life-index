# Architecture and navigation

## File ownership

| File | Responsibility |
| --- | --- |
| `index.html` | Static shells, IDs, baseline styles, first-paint welcome logic, external Leaflet load |
| `app.js` | ES-module entry with an IIFE; Leaflet, metric registry, state, scoring, search, controls, persistence |
| `interface.js` | `GROUPS`, grouped sliders, moves controls into desktop non-modal panels/mobile bottom modals, responsive navigation |
| `interface.css` | Loaded after baseline styles; calm visual treatment, z-index tokens, mobile sheets |
| `presets.js` | Four editable preference and rent-budget scenarios |
| `questionnaire.js` | `setupQuestionnaire()`; guided answers converted into an editable index |
| `rental-data.js` | CSV validation, point-in-polygon assignment and matching asking-rent summaries |
| `scripts/prepare_*.py` | Offline source transformation; browser never invokes these |
| `sources/index.html` | Generated by `scripts/prepare_sources_page.py` |
| `vision/index.html` | Hand-maintained public purpose and roadmap |
| `.github/workflows/pages.yml` | Explicit asset allowlist copied into `_site`, then Pages deployment |

There is no bundler, application server, framework or account backend. `npm run dev` serves the repository on port 4173. Use relative asset/link paths for the `/bengaluru-life-index/` hosting prefix.

## Initialization

`load()` fetches wards first, rebuilds the layer and fits the city. It then fetches assemblies, amenities, destinations, rent and greenery, constructs category controls and metric inputs, co-locates them, and calls `setupInterface()`. Configuration restoration and scoring follow data setup. The HTML opens the welcome before slow external scripts/data finish; `questionnaire.js` attaches behavior later. Preserve that first-paint ordering.

**Important:** `setupInterface()` moves actual DOM nodes, retaining IDs and handlers. Do not duplicate inputs. Append a dialog to the document before moving/querying its controls via `getElementById`. Group setup depends on generated controls, so do not run it before they exist.

## State and update paths in app.js

- `indicators`: metric definitions and mutable inclusion, weight and reverse preference.
- `enabled`: visible amenity categories, initially empty and independent of metric inclusion. Visibility buttons are moved into the map layer strip; `referenceVisible` separately controls the destination marker.
- `features`, `metrics`, `byCategory`: geometry, ward aggregates and point directory.
- `cachedParts`, `rawValues`, `scores`: cached base components, raw units and current scores.
- `metricView` (`none`, `custom`, metric key) and `indexOn`: selected coloring.
- `corp`, `query`, `selected`: current filters and selected ward.
- `costSettings`, `listingRecords`, `reference`: dynamic scoring inputs.

`calculate()` computes scores then calls `updateIndex()`. Static components are cached; reference and cost are recalculated. `updateIndex()` syncs group controls, ward colors, details, rankings and persistence. `rebuild()` replaces ward geometry after filters and refreshes POIs. `refreshPOIs()` handles visibility and transit legend. `select()` highlights/frames a ward and replaces rankings with details. `activateWeightedIndex()` also restores visible ward styling.

## Configuration contract

`CONFIG_VERSION=1`, model `ward-model-v1`, draft key `bengaluru-life-index:draft:v1`. Settings include name/description, preset, view, snapshot signature, costs, metric `{enabled,weight,reverse}` and optional reference. Existing individual weights are 0–100; group weights are derived totals, not new serialized fields.

Shared `#config=` URL-safe base64 JSON takes priority over the local draft. Unknown metric keys are ignored; known settings are validated. Preserve backward defaults for older cost settings. `requireRentCoverage` is an optional boolean defaulting to false, including older configurations; this intentionally replaces the former automatic missing-rent veto with labelled partial scores. Snapshot signatures warn of changed data; they do not freeze scores.

Drafts include reference coordinates locally. Shared links/exports omit the reference by default; inclusion requires the explicit checkbox. Imported rent rows remain in tab memory and are not persisted/shared. No hidden location transmission or backend upload should be added.

Rent settings serialize `rentBudget` (₹10k–₹100k), not total spending. Legacy configurations with `monthlyBudget` and `nonRent` migrate to their difference clamped to that range, then drop the old fields. The metric key `cost_of_living` is retained for compatibility but its visible label and calculation are rent-only.

Starbucks-only `starbucks_count` was retired in favor of `coffee_chain_count`. Older settings for the retired factor are ignored with an explicit message when selected; they are not silently transferred to the broader factor. Other metrics remain compatible. The chain classification version is included in the source signature, so changed café/chain aggregates trigger the usual snapshot notice.

`costSettings.includeInferredRent` is a validated optional boolean, default true. `rentForWard()` prefers the nearby locality proxy, then the separately generated inference when eligible. Imported listing summaries and specific housing/furnishing filters never use tenant inference. Coverage UI separates nearby and inferred counts.
